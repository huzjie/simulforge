# simulforge · 技术拆解：把「边说边译」做成可复现的工程框架

> 一句话：同声传译的工程难点不在模型，而在「流式增量 + 读/写策略 + 质量-延迟权衡」三个工程问题。本文拆解 Hy-SimulMT（腾讯混元同传大模型，30B-A3B，StreamLAAL≈3s）背后的可复用方法，并给出能直接照抄的提示词与配置片段。

## 背景（一段，够引出技术即可）

2026-10-26 腾讯混元开源 Hy-SimulMT，中英语音到语音实时翻译 + 实时音色克隆，延迟约 3 秒，超过主流开源同传模型和多数商业 API。它真正值得学的不是「又一个 30B 模型」，而是同传这条赛道独有的工程约束：**音频是持续流进来的，系统必须在词级增量决策，而不是等句子结束。**

## 干货 1：读/写策略是延迟的唯一决定量

同传每一步只有两个动作：READ（再读一个源词）或 WRITE（吐一个目标词）。这个 `(source_read, target_written, confidence) -> READ|WRITE` 的函数，完全决定了延迟。四种策略、延迟各不相同：

| 策略 | 思路 | 平均滞后 |
|------|------|----------|
| wait-k | 读 k 个源词后交替读写 | ≈ k |
| prefix-to-prefix | 源/目标前缀比例对齐 | 自适应（适合中英词率差异大的场景）|
| confidence-adaptive | 置信度超阈值才 WRITE | 随模型变强而下降 |
| MMA | 硬单调注意力对齐 | 可学习 |

**可复用结论**：策略与模型解耦。换策略只改延迟、不动模型权重，于是「延迟优先」和「质量优先」可以做成两个 yaml 配置一键切换，而不是重新训练。

## 干货 2：级联 vs 直通，是「错误累积」与「可观测性」的取舍

- 级联（ASR→MT→TTS）：能拿到转写文本、好调试，但三级误差累积、延迟叠加。
- 直通 S2S：少两级、延迟更低、无级联错误，但丢了转写这个可观测中间态。

生产里两条路都留着，`config.s2s.direct` 切换。

## 干货 3：延迟指标要「可证伪」，不能拍脑袋

```
AL        = (1/τ) Σ_i (g_i − (i−1)/γ)      # g_i = 吐第 i 个目标词时已读源词数
StreamLAAL = LAAL × 秒/词                    # RealSI 用的秒级延迟
```

用策略的 read/write 轨迹**直接算**，而不是估算。有了这个，「好模型 = 质量、延迟双轴同时变好」才能被证伪。

## 干货 4：音色克隆 = 说话人嵌入的加权混合

```
hyp = boost · ref + (1 − boost) · noise
similarity = cosine(ref, hyp)
boost = (skill − 0.5) × 2
```

skill=0.5（boost=0）≈随机音色；skill=1.0（boost=1）完全还原。训练用 `skill += lr·(1−skill)` 单调爬升，保证每一脚都朝最优走、不震荡。

## 可复用提示词（可直接抄）

流式 ASR（增量转写、可回改）：

```
你是同传场景的流式语音识别引擎。对持续到达的音频增量转写：每个词一旦足够置信就吐出局部假设，
后续上下文若改变早前判断则回改。保持源语言、不要翻译。
输入: {audio_chunk}
输出: 增量增长的转写 token
```

同传读/写策略：

```
你是同传读/写策略。每一步决策：READ 再读一个源词，还是 WRITE 再吐一个目标词？
在置信度高时尽早吐、不确定时多读。source_read={} target_written={} confidence={}
```

## 踩坑与解法（都写进了实现）

1. **自适应策略会死锁**：置信度长期低于阈值时既不读也不吐。解法：加 `patience`——连续 N 步不吐就强制 WRITE。
2. **wait-k 的 AL 恒等于 k**：想测「策略改进」不能用 wait-k 当 baseline 对比自适应，因为它俩的 AL 定义域不同；要对比就对齐在同一个 read/write 轨迹上算。
3. **余弦对幅度不敏感**：度量音色相似度用 cosine 没问题，但度量「翻译质量」若用 cosine 会漏掉幅度差异；质量改用 BLEU/相对误差。
4. **中英词率差异**：中文紧凑、英文词多，固定 wait-k 会歪；用 prefix-to-prefix 按比例对齐更稳。
